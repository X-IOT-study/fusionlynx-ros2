# FusionLynx SLAM 参数工程测定方案

## 1. 适用范围

本文档用于说明以下配置文件中各参数的工程测量、标定、验证和记录方法：

```text
src/fusionlynx/fusionlynx_slam/config/fusionlynx_slam.yaml
```

该文件是传递给 `state_fusion_backend_node` 的系统级参数文件，不包含
FAST-LIO 前端参数。FAST-LIO 继续使用其自身软件包中的 UniLidar 配置，
RTAB-Map 参数由 `fusionlynx_mapping` 提供。

当前系统数据链路为：

```text
MotionCore 轮式里程计
    + FAST-LIO /fast_lio/odom
    -> state_fusion_backend
    -> /odom 与 odom -> base_link
    -> RTAB-Map
```

参数测定必须遵循以下顺序：

```text
接口与 TF 验证
    -> 时间戳验证
    -> 传感器外参验证
    -> 运动与传感器噪声测量
    -> 固定时窗与鲁棒核选择
    -> 健康判据标定
    -> 独立数据验证
```

不得使用估计器噪声参数掩盖坐标系、时间戳或传感器标定错误。发现这类
问题时，应先修正系统接口，再进行数值标定。

## 2. 参数分类

配置参数分为四类：

| 分类 | 含义 | 处理方式 |
|---|---|---|
| 接口契约参数 | 话题、坐标系、所有权和启停策略 | 根据运行系统验证，不通过统计优化确定 |
| 传感器标定参数 | 物理外参、传感器噪声和运动模型不确定性 | 通过硬件测量或记录数据估计 |
| 设计扫描参数 | 固定时窗、鲁棒损失和协方差缩放 | 根据精度、连续性和计算开销进行参数扫描 |
| 兼容参数 | 为未来因子适配器保留、当前 `Pose3` 后端未启用的参数 | 保持关闭并明确记录其未生效状态 |

当前后端在固定时窗 `Pose3` 因子图中使用轮式因子和 FAST-LIO 因子。
MotionCore IMU 和磁场数据在启用健康监视时参与 LIO 可靠性判断，但当前
并未作为直接定位因子加入因子图。

## 3. 参数清单与测定方法

### 3.1 接口与系统契约参数

以下参数不能通过轨迹优化确定，而应与 ROS 2 运行图、URDF/Xacro 和系统
架构契约进行核对。

| 参数 | 当前作用 | 验证方法 |
|---|---|---|
| `wheel_odom_topic` | 轮式里程计输入 | 使用 `ros2 topic info -v` 和单条消息检查 |
| `imu_topic` | 健康监视 IMU 输入 | 检查发布者、QoS、时间戳和 frame |
| `mag_topic` | 健康监视磁场输入 | 检查发布者、QoS、时间戳和 frame |
| `fastlio_topic` | FAST-LIO 位姿观测 | 检查 `/fast_lio/odom` 和协方差布局 |
| `fused_odom_topic` | 权威融合里程计输出 | 确认 `/odom` 只有一个权威发布者 |
| `diagnostics_topic` | 诊断输出 | 检查诊断发布者和更新频率 |
| `wheel_odom_frame` | 轮式里程计父坐标系 | 与 `header.frame_id` 对比 |
| `wheel_child_frame` | 轮式里程计子坐标系 | 与 `child_frame_id` 对比 |
| `lio_world_frame` | FAST-LIO 位姿父坐标系 | 与 `/fast_lio/odom.header.frame_id` 对比 |
| `lio_child_frame` | FAST-LIO 位姿子坐标系 | 与 `/fast_lio/odom.child_frame_id` 对比 |
| `odom_frame` | 融合里程计坐标系 | 检查 `/odom.header.frame_id` |
| `base_link_frame` | 机器人机体坐标系 | 检查 `/odom.child_frame_id` 和 TF |
| `publish_tf` | 动态 TF 发布所有权 | 确认只有后端发布 `odom -> base_link` |
| `fusion_profile` | 因子组合预设 | 确认与当前实验条件一致 |
| `use_wheel_odom`、`use_fast_lio` | 因子来源开关 | 记录每个消融实验的开关状态 |
| `use_lio_health`、`use_static_anchor` | 健康监视和静止锚定开关 | 在实验记录中明确记录 |

在所有数值标定开始前，必须执行：

```bash
ros2 topic info -v /motioncore/wheel_odom
ros2 topic info -v /fast_lio/odom
ros2 topic echo /motioncore/wheel_odom --once
ros2 topic echo /fast_lio/odom --once
ros2 topic info -v /odom
ros2 run tf2_ros tf2_echo odom base_link
ros2 run tf2_ros tf2_echo base_link lidar_link
ros2 run tf2_tools view_frames
```

验收条件：

1. `/odom` 只有一个权威发布者。
2. `state_fusion_backend` 是唯一的动态 `odom -> base_link` 发布者。
3. FAST-LIO 不发布竞争性的动态里程计 TF。
4. 消息中的 frame 与 YAML 参数一致。
5. FAST-LIO 协方差遵循 ROS `Odometry` 标准顺序。
6. 时间戳没有负值、倒退或异常超前现象。

### 3.2 LiDAR 到机体的物理外参

| 参数 | 状态 | 测量方法 |
|---|---|---|
| `lio_lidar_to_base_xyz` | 当前生效的平移外参 | 测量 LiDAR 原点相对于 `base_link` 原点的位置 |
| `lio_lidar_to_base_rpy` | 当前生效的旋转外参 | 确定 LiDAR 轴相对于机器人机体轴的姿态 |

当前转换关系为：

$$
T_{\mathrm{camera\_init},\mathrm{base}}
=
T_{\mathrm{camera\_init},\mathrm{lidar}}
T_{\mathrm{lidar},\mathrm{base}}.
$$

平移测量必须依据机械基准面或安装孔位，不能以传感器外壳的视觉中心代替
传感器坐标原点。至少记录：

- LiDAR 安装孔或支架基准；
- `base_link` 原点定义；
- 各坐标轴的正方向；
- 杠杆臂测量不确定度；
- 拆装后安装重复性。

旋转外参测量步骤：

1. 将机器人放置在水平地面。
2. 标记 `base_link` 的前、左、上方向。
3. 测量 LiDAR 横摆角相对于机器人前向轴的角度。
4. 使用水平仪或点云平面拟合检查 roll 和 pitch。
5. 让机器人原地旋转，检查 FAST-LIO 位姿增量方向和符号是否正确。

外参必须通过 TF 和运动两方面验证：

- 将显式配置转换与 URDF 静态 TF 进行比较；
- 直线行驶，检查是否产生异常横向位移；
- 原地旋转，检查 LiDAR 杠杆臂是否引入虚假平移；
- 与 `fast_lio_base_test.launch.py` 的转换结果进行比较。

最终记录外参及其不确定度。如果显式配置和 URDF 中的静态变换不一致，
必须先解决所有权冲突，不能继续采集精度数据。

### 3.3 时间与缓存参数

| 参数 | 测量内容 | 选择规则 |
|---|---|---|
| `frequency` | 定时器周期、输出频率和回调处理时间 | 满足输出要求且不发生定时器超时 |
| `sensor_timeout` | FAST-LIO 和轮式输入的接收年龄、消息间隔 | 大于正常接收年龄的 99% 分位值加裕量，小于允许的最大过期时间 |
| `max_time_delay` | 时钟对齐后的跨传感器事件时间差 | 大于跨传感器配对误差 99% 分位值加时间不确定度 |
| `max_future_stamp` | 消息相对节点时间的超前量 | 大于正常最大超前偏差加裕量，超过该值的消息应拒绝 |
| `queue_size` | 输入速率、突发数据量和缓存占用 | 大于最大突发量，并覆盖 `速率 * reorder_window` |
| `reorder_window` | 消息乱序到达延迟 | 取迟到消息延迟的 99% 或 99.9% 分位值加裕量 |
| `clock_offset_tolerance` | 多设备时钟偏移量 | 大于最大绝对时钟偏移和测量不确定度 |
| `diagnostics_publish_rate` | 诊断开销和状态观测需求 | 足以观察状态变化且不影响估计实时性 |

必须将单调接收时间与消息头时间分开处理。如果各设备使用独立时钟，
不能只比较两个消息头时间来估计传输延迟。

对于每个 rosbag，计算：

$$
\Delta t_{\mathrm{arrival}}
=
t_{\mathrm{receive}}-t_{\mathrm{header}},
$$

$$
\Delta t_{\mathrm{pair}}
=
t_{\mathrm{wheel}}-t_{\mathrm{lio}},
$$

以及乱序到达延迟：

$$
\Delta t_{\mathrm{late}}
=
t_{\mathrm{processed}}-t_{\mathrm{arrival\ order}}.
$$

至少统计中位数、95% 分位值、99% 分位值和最大值。同时记录：

- 丢失消息数量；
- 缓存溢出次数；
- 过旧消息拒绝次数；
- 未来时间戳拒绝次数；
- 传感器超时次数。

有效配置应满足目标运动负载下不发生缓存溢出，且不能通过过大的时间窗口
掩盖持续性的时钟错误。

建议初始扫描：

```text
frequency:          25, 50, 75 Hz
sensor_timeout:     正常数据 p99 + 裕量
max_time_delay:     正常配对误差 p99 + 裕量
reorder_window:     迟到延迟 p99 + 裕量
queue_size:         由速率和窗口计算，再增加突发量裕量
```

### 3.4 固定时窗与图优化参数

| 参数 | 测量方法 | 验收条件 |
|---|---|---|
| `window_duration` | 在相同 rosbag 上扫描 2、4、6、8、12 s | 选择精度和恢复行为稳定后的最短窗口 |
| `robust_kernel` | 在正常和异常数据上比较 `gaussian`、`huber` 和 `none` | 在误差和连续性之间取得最佳折中 |
| `robust_kernel_scale` | 分析白化残差，在可接受残差的 90% 到 99% 分位附近局部扫描 | 抑制异常值，但不能压制有效横向运动 |
| `lio_degraded_scale` | 扫描协方差放大倍数，记录因子决策和融合轨迹 | 退化 LIO 不得主导轮式约束，正常 LIO 仍应发挥作用 |
| `recovery_stable_count` | 测量故障后需要连续多少帧稳定输出才能重新接入 | 取能避免短时恢复尖峰再次接入的最小值 |

`window_duration` 必须同时评估：

- 输出延迟；
- 单次更新耗时；
- CPU 占用；
- 内存占用；
- 活跃状态和因子数量；
- ATE 与 RPE；
- LIO 间断期间的行为；
- 恢复对齐跳变量。

固定时窗变大可能改善局部一致性，但也会增加边缘化和增量优化开销。
最终选择应满足精度、输出延迟和计算资源预算，而不是只选择单条序列上
误差最低的配置。

### 3.5 轮式因子噪声

| 参数 | 含义 | 测量方法 |
|---|---|---|
| `wheel_x_sigma` | 前向相对平移不确定度 | 直线行驶时与外部参考比较轮式增量 |
| `wheel_y_sigma` | 横向相对平移不确定度 | 纯横移时与外部参考比较轮式增量 |
| `wheel_yaw_sigma` | 相对偏航不确定度 | 原地旋转时与外部参考比较轮式偏航增量 |

至少采集以下运动：

1. 前向直行；
2. 后向直行；
3. 纯横移；
4. 顺时针原地旋转；
5. 逆时针原地旋转；
6. 斜向运动；
7. 平移与旋转组合运动；
8. 多次起步和刹停；
9. 轮滑及快速加减速。

对每种运动，将轮式轨迹与外部参考对齐，并在相同时间间隔上计算相对增量
误差：

$$
e_{\mathrm{wheel},k}
=
\operatorname{Log}\left(
\Delta T_{\mathrm{reference},k}^{-1}
\Delta T_{\mathrm{wheel},k}
\right).
$$

使用中位数绝对偏差估计每个受约束自由度的鲁棒一倍标准差：

$$
\hat{\sigma}=1.4826\,\operatorname{median}\left(
|e-\operatorname{median}(e)|
\right).
$$

随后加入重复性和轮滑裕量。不得只用一次低速测试确定
`wheel_y_sigma`，因为麦克纳姆平台的横向滑移是预期误差来源。最终参数
应足够保守，避免错误的横向运动学模型强行牵引 FAST-LIO 轨迹。

### 3.6 LIO 因子噪声

| 参数 | 含义 | 测量方法 |
|---|---|---|
| `lio_position_sigma` | LIO 因子最小系统级平移标准差 | FAST-LIO 相对误差与可信参考轨迹比较 |
| `lio_rotation_sigma` | LIO 因子最小系统级旋转标准差 | FAST-LIO 相对旋转误差与可信参考比较 |
| `lio_z_sigma_scale` | 垂向运动额外不确定度倍数 | 估计垂向误差与水平误差的比例，并在不同地形验证 |
| `fallback_pose_sigma` | 两种主要运动因子都不可用时的弱先验 | 验证其不会过度约束轮式预测或形成虚假的位姿保持 |

使用 FAST-LIO 协方差前，必须检查其有效性。后端将配置中的 LIO sigma
作为系统噪声下限，是因为前端输出的协方差可能对外部融合轨迹过于乐观。

每条序列执行：

1. 将 FAST-LIO 与参考轨迹对齐；
2. 在相同事件时间计算相对位姿误差；
3. 分离平移、roll、pitch、yaw 和 $z$；
4. 计算误差偏置和鲁棒尺度；
5. 检查 FAST-LIO 输出协方差；
6. 比较预测协方差和经验平方误差；
7. 将配置的噪声下限设置为不小于重复性测量得到的尺度。

不得使用融合后的 `/odom` 估计 LIO 噪声，否则噪声模型会与被测输出相互
引用。应使用动作捕捉、RTK、测量得到的室内参考轨迹或独立验证过的参考。

对于 `lio_z_sigma_scale`：

$$
s_z=
\frac{\hat{\sigma}_z}{\hat{\sigma}_{xy}},
$$

并在以下条件验证：

- 平地运动；
- 通过门槛；
- 坡道或不平地面；
- 原地旋转；
- 静止。

该参数应减少虚假的垂向运动，但不能将真实坡道运动压平。

### 3.7 平面运动软先验

| 参数 | 测量方法 |
|---|---|
| `use_planar_prior` | 在平地、坡道和门槛条件下比较打开与关闭两种配置 |
| `planar_z_sigma` | 根据目标地面上的可接受垂向偏差确定 |
| `planar_roll_sigma` | 根据正常运动中的实测 roll 波动确定 |
| `planar_pitch_sigma` | 根据正常运动中的实测 pitch 波动确定 |
| `planar_reference_z` | 测量局部地面与机体参考的高度，不能在坐标原点有偏移时盲设为零 |
| `planar_reference_roll` | 估计静止时机体相对于局部坐标系的姿态 |
| `planar_reference_pitch` | 估计静止时机体相对于局部坐标系的姿态 |

平面先验是有限协方差软约束，不是硬约束。参数应根据平台物理运动范围
和地面粗糙度确定。过小的 sigma 可以提高平地稳定性，但会压制坡道和
障碍物上的真实运动。

必须执行打开和关闭平面先验的对比实验，至少比较：

- 垂向漂移；
- roll 和 pitch 波动；
- 水平 ATE/RPE；
- 坡道高度变化；
- 通过门槛时的连续性；
- 因子残差分布。

### 3.8 静止检测与静止处理

| 参数 | 测量方法 |
|---|---|
| `stationary_speed_threshold` | 测量真实静止时轮速分布，以及预期最慢运动速度 |
| `stationary_yaw_rate_threshold` | 测量真实静止时偏航速度分布，以及预期最慢旋转速度 |
| `static_gyro_threshold` | 测量静止期间陀螺仪模长分布 |
| `static_min_duration` | 测量起步和刹停瞬态持续时间，取大于最长瞬态的值 |
| `stationary_lio_scale` | 在静止 LIO 抖动数据上扫描协方差放大倍数 |
| `stationary_pose_sigma` | 根据静止融合位姿重复性和允许的保持误差确定 |
| `zero_velocity_sigma` | 当前 `Pose3` 后端未实现独立零速度因子，不作为有效参数标定 |

在每种相关运行条件下至少采集三段静止数据。使用轮式指令、编码器状态
和独立运动参考共同标记真实静止区间。

阈值应根据两类分布确定：

- 静止噪声分布；
- 最小有意义运动分布。

静止阈值应高于静止噪声的 99% 分位值，同时低于系统必须保留的最小运动。
必须额外验证慢速横移和慢速偏航，因为它们最容易被误判为静止。

只有在静止检测器确定后，才能调整 `stationary_lio_scale` 和
`stationary_pose_sigma`。否则，过度放大的协方差可能掩盖检测器错误。

目标行为为：

```text
确认静止 -> 保存一个软锚点 -> 降低 LIO 影响
恢复运动 -> 释放软锚点 -> 保持输出连续
```

### 3.9 LIO 健康监视参数

| 参数 | 测量方法 |
|---|---|
| `lio_nis_degraded_threshold` | 根据正常 NIS-like 统计量的高分位值确定，再用标注退化数据验证 |
| `lio_nis_failed_threshold` | 使用失败与可接受观测的 ROC 或代价函数确定 |
| `lio_consistency_degraded_threshold` | 根据正常轮式/IMU 一致性得分的高分位值确定 |
| `lio_consistency_failed_threshold` | 根据已标注不一致观测与正常观测的分离程度确定 |
| `wheel_consistency_position_sigma` | 正常轮式-LIO 平面相对位置误差的鲁棒尺度 |
| `wheel_consistency_yaw_sigma` | 正常轮式-LIO 相对偏航误差的鲁棒尺度 |
| `imu_consistency_yaw_sigma` | 正常 LIO 偏航增量与 IMU 积分偏航增量差异的鲁棒尺度 |
| `max_pose_jump` | LIO 时间间隔内最大物理可行平移加不确定度裕量 |
| `max_pose_jump_yaw` | LIO 时间间隔内最大物理可行偏航变化加不确定度裕量 |
| `mag_norm_relative_change_threshold` | 正常连续磁场模长变化的高分位值 |
| `mag_field_norm_min`、`mag_field_norm_max` | 磁场标定范围；当前除非被验证路径使用，否则属于兼容字段 |

健康参数标定时必须启用健康监视。当前配置的 profile `D` 会关闭
`use_lio_health`，因此应使用明确的健康实验 profile，或使用
`fusion_profile: custom` 并设置 `use_lio_health: true`。不能混合使用
健康监视开启和关闭的数据来估计同一组阈值。

#### NIS-like 统计量测定

1. 采集正常运行序列。
2. 使用在线代码完全相同的六维对角协方差归一化公式计算统计量。
3. 根据正常数据高分位值设置降级阈值。
4. 采集受控退化和失败序列。
5. 根据检测率、误隔离率和检测延迟设置失败阈值。
6. 使用未参与标定的序列进行最终验证。

一致性尺度应使用在线监视器相同的残差定义：

$$
e_{\mathrm{wheel}}
=
\operatorname{Log}\left(
\Delta T_{\mathrm{wheel}}^{-1}
\Delta T_{\mathrm{LIO}}
\right),
$$

从中提取平面位置和偏航分量，并计算：

$$
e_{\mathrm{imu,yaw}}
=
\operatorname{wrap}\left(
\Delta\psi_{\mathrm{LIO}}-\Delta\psi_{\mathrm{IMU}}
\right).
$$

使用正常运行数据的 MAD 鲁棒尺度估计三个 sigma，然后在慢速横移、慢速
偏航和正常轮滑条件下检查误报警率。一致性得分除以 sigma 后成为无量纲
量，因此修改三个 sigma 后必须重新检查 `3.0` 和 `6.0` 两个退化/失败
阈值。

健康监视器会将上述证据映射为协方差缩放、因子接纳和恢复对齐。至少记录：

```text
lio_state
lio_nis
lio_innovation_norm
lio_wheel_consistency
lio_imu_consistency
lio_mag_consistency
lio_covariance_scale
lio_covariance_source
factor decision
recovery alignment
```

正常运行误报率应同时按每段序列和每 1000 次 LIO 更新统计，不能只报告
观测到的最大 NIS。

对于位姿跳变阈值，令 $v_{\max}$ 和 $\omega_{\max}$ 为测试得到的
平台运动上限，令 $\Delta t_{\max}$ 为允许的最大 LIO 时间间隔：

$$
d_{\max}=v_{\max}\Delta t_{\max}+d_{\mathrm{margin}},
$$

$$
\psi_{\max}=\omega_{\max}\Delta t_{\max}+\psi_{\mathrm{margin}}.
$$

裕量必须包含测量重复性、时间戳不确定度和 LiDAR 到机体的杠杆臂影响。

### 3.10 当前定位图中未启用的参数

以下字段在节点接口中声明并传递，但当前不定义有效的 IMU 或磁场定位因子：

```text
gravity
use_motioncore_imu
use_magnetic_heading_factor
mag_calibration_valid
zero_velocity_sigma
imu_accel_sigma
imu_gyro_sigma
imu_bias_accel_sigma
imu_bias_gyro_sigma
mag_noise_sigma
mag_field_norm_min
mag_field_norm_max
```

当前后端将 IMU 和磁场数据保留在定位图之外，仅在已实现的健康处理路径
中使用。不得将这些值报告为已经标定的因子参数，也不得声称修改它们
会改变当前融合位姿。

只有在明确实现并单独验证以下功能后，才应重新标定这些参数：

- IMU 预积分；
- 速度和 bias 状态；
- 独立零速度因子；
- 磁航向因子。

### 4.2 运动实验矩阵

至少采集：

1. 静止保持；
2. 前后直行；
3. 纯横移；
4. 纯偏航旋转；
5. 组合平面运动；
6. 多次起停；
7. 接近静止阈值的慢速运动；
8. 快速加速和刹车；

10. 长走廊或低特征环境；

### 4.3 外部参考

优先使用：

- 动作捕捉；
- 测量得到的室内参考轨迹；
- 环境允许时的 RTK GNSS；
- 单独验证过的参考轨迹。

如果没有度量级参考，只能报告相对重复性、连续性、残差以及故障/恢复
行为。不能根据 RViz 截图或单次轨迹叠加声称绝对精度提升。

## 5. 标定与验证流程

### 步骤 0：冻结接口

验证话题、frame、TF 所有权、时间戳单调性、QoS 和协方差顺序。数值标定
期间不得改变 launch 组合。

### 步骤 1：标定外参与时间

解决 LiDAR 到机体外参以及时钟/到达时间统计问题。每次重新安装传感器后，
重新执行直线、横移和原地旋转检查。

### 步骤 2：测量单传感器重复性

分别估计轮式和 FAST-LIO 的相对位姿误差。不得使用融合输出作为其中任一
传感器自身噪声模型的参考。

### 步骤 3：选择因子 sigma

根据经验鲁棒尺度设置轮式和 LIO 噪声下限，然后验证白化残差。如果正常
残差系统性地远大于一倍标准差，说明协方差过度乐观或观测模型不完整。

### 步骤 4：选择平面与静止处理

使用平地、坡道、门槛和慢速运动数据调整平面先验与静止检测参数，确认
系统不会把真实运动误判为静止锚定。

### 步骤 5：选择固定时窗与鲁棒损失

在同一组 rosbag 上完成固定时窗和鲁棒核扫描，选择同时满足精度、连续性
和计算开销约束的最小配置。

### 步骤 6：标定健康门限

启用健康监视，标记正常、退化和失败区间，调整 NIS、一致性、跳变、缩放
和恢复参数。完整状态序列应为：

```text
HEALTHY -> DEGRADED -> FAILED -> RECOVERING -> HEALTHY
```

### 步骤 7：留出数据验证

使用未参与标定的新路线或新运行条件。查看最终测试集结果后不得继续修改
阈值。最终报告至少包含：

- ATE 和 RPE；
- 静止位置与姿态抖动；
- 健康监视正常误报警率；
- 失败检测率；
- 检测延迟；
- 因子接纳/拒绝率；
- 恢复持续时间；
- 恢复位姿跳变；
- 输出频率与延迟；
- CPU 与内存；
- 消息拒绝次数；
- 队列溢出次数。
